# DOSO 机器狗量产网络与遥控器更换方案

## 目标

更换 G20 或机器狗后，现场仍能完成本地控制；没有路由器或互联网时，控制链路仍可用；云端登录、设备绑定和本地控制相互隔离。

远程管理须由用户主动开启，其数据边界、关闭确认及验收要求见 [远程管理与数据边界](../production/DOSO_REMOTE_MANAGEMENT_CONSENT.md)；该能力尚未完成端到端实现与验收。

## 2026-11-12 当前采用的方案

森哥已确认采用机器狗自身Wi-Fi AP作为默认本地连接方式。首版流程为机器狗开机开启带独立密码的热点，G20或手机加入后读取状态并使用本地控制；外部Wi-Fi作为可选联网入口。

热点侧规划固定地址为`192.168.50.1/24`，Brainstem目标端口为`13145`。该地址由机器狗的NetworkManager热点连接配置保存，客户端地址由DHCP自动分配。配置部署后需要验收重启后的固定地址、DHCP分配、服务监听及客户端真实状态读取。当前尚无这条热点链路完整通过的证据。

NetworkManager的热点连接使用`ipv4.method=shared`，并显式配置`ipv4.addresses=192.168.50.1/24`和自动连接。单独的热点网络可以使用相同的网关地址，每台机器狗通过独立SSID和设备身份区分。配置时须核对现有网段，防止与同时连接的外部网络重叠。[NetworkManager官方IPv4配置](https://networkmanager.pages.freedesktop.org/NetworkManager/NetworkManager/nm-settings-nmcli.html)

BLE另有两项缺口，当前Windows与机器狗USB控制器之间的GATT读取不稳定，以及完整Wi-Fi凭据写入/NetworkManager执行/结果通知尚未接通。热点连接先独立验收，BLE后续作为发现和配网辅助入口。最新证据见[BLE配网记录](../production/ROBOT_BLE_PROVISIONING.md)。

## 网络接口规划

2026-11-12现机检查只有wlan0，报告支持AP，驱动明确报告不支持多接口组合。已有AP配置原绑定不存在的wlan1，已备份后修正为wlan0并保留手动启用，固定地址仍为192.168.50.1/24。当前连接继续为192.168.66.64，热点真实关联与控制入口待验收。[现机证据与恢复步骤](../../artifacts/network/20261112-system-inventory/README.md)

首版由wlan0在热点与外部Wi-Fi之间切换。切换流程包含管理连接恢复与Brainstem监听地址接线，当前服务只监听192.168.66.64:13145。

以下双接口方案保留为后续扩展，需要有对应的硬件和驱动证据后实施。

```text
wlan0  外部 Wi‑Fi 客户端
       云端登录、设备绑定、日志和更新

wlan1  机器狗本地 AP
       G20/维护设备的本地控制和配对
```

历史连接地址与热点规划地址如下，分别按已有验收记录和待部署配置理解。

- 外部 Wi‑Fi：`192.168.66.64`
- 本地热点网关规划：`192.168.50.1`，热点完整链路待验收

G20 连接热点后应获得 `192.168.50.x` 地址，并把 `192.168.50.1` 作为本地 Brainstem 地址；G20 连接外部 Wi‑Fi 时才使用 `192.168.66.64`。

## 量产时不能依赖的东西

- 不能所有机器狗共用一个 SSID 和密码。
- 不能把机器狗 IP 当成控制身份。
- 不能只按来源 IP 放行控制。
- 不能让云端在线状态决定本地急停或租约失效。

## 量产配对模型（后续阶段）

当前阶段沿用已授权的QA局域网工程验证。下面的量产身份步骤独立安排，当前优先验收开机热点、真实状态读取和本地控制。

1. 每台机器狗生成唯一设备身份和唯一热点凭据。
2. 热点 SSID 使用机器狗短 ID，例如 `DOSO-AB12CD`；生产标签或二维码包含 SSID、一次性配对码和设备短 ID，不在公共代码中保存密码。
3. Brainstem 使用每台机器狗独立的 server certificate；G20 使用 Android KeyChain 中的 controller certificate。
4. 第一次配对通过二维码或本地 BLE enrollment 交换设备公钥/挑战，不把客户端私钥传到聊天、APK 或 ADB。
5. Brainstem 以 mTLS principal 作为控制身份，控制租约仍只有一个持有者。
6. 更换 G20 时撤销旧 controller certificate，再签发新 controller certificate；机器狗 IP 和服务单元不需要重配。
7. 更换机器狗时，DOSO 通过设备短 ID 和设备身份挑战确认新设备，不把旧机器狗的证书或控制权带过去。

## 当前实现需要补的量产能力

- 当前已确认现机AP能力及原配置接口错误，接下来完成热点广播、DHCP、客户端关联、重启和失败恢复验收。
- 核对Brainstem热点侧监听地址及来源限制，使用客户端DHCP地址完成真实读取和租约验收。较早的单来源IP限制按现机部署再核对。
- 在 DOSO 中提供“机器狗热点”和“外部局域网”两个连接档案，切换网络后重新读取状态和身份，不自动继承控制租约。
- 现有局域网原生gRPC已接状态及动作、控制租约和ACK/失联保护。热点部署后复验服务可达、控制权、停止保护及持续控制，当前代码与实测范围见[功能交付待办](../production/DOSO_FUNCTIONAL_REQUIREMENTS_AND_DELIVERY_BACKLOG.md)。量产证书配对独立推进。
- G20 真机验收至少覆盖：热点不可用、热点重启、外部 Wi‑Fi 断开、G20 更换、旧证书撤销、控制租约抢占和断线清零。

## 当前工程验证顺序

```text
热点配置与恢复路径就绪
→ 启用热点并由客户端加入
→ 客户端获得地址
→ 热点侧读取Brainstem真实状态
→ 按现场条件请求控制权
→ 初始零速ACK与控制
→ 释放租约或失联停止
```

热点切换及开机自动连接须在客户端关联、Brainstem服务地址和恢复路径验证完成后启用。

## 量产控制安全顺序

```text
发现热点
→ 获取本地地址
→ 设备身份挑战
→ mTLS 只读状态
→ AcquireControl
→ 初始零速 ACK
→ 续租/控制
→ 释放租约或 deadman 清零
```

任何一步失败都不发送站立、坐下、动力或移动指令。
