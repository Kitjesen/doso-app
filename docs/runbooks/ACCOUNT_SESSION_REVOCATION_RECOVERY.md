## What this slice does not solve

- The safety screen's unknown-result lock is local to its current React mount.
- Typed outcomes stop one invocation's automatic fallback. They do not stop a fresh invocation after page remount, restart, another device or another account flow.
- `sessionService` does not freeze expected user/session identity before dispatch or recheck it before SDK sign-out. An account switch while awaiting a response remains a separate high-impact risk.
- `AuthProvider` session-preparation generations are mount-local. Initial `getSession` and later auth events can ingest a session again after a remount. A module singleton alone is not durable revocation evidence.
- SDK sign-out and installation-ID storage can hang. Racing a sign-out call is not a safe cancellation because a late SDK completion can still mutate auth storage.
- Client access-token parsing is only suitable to partition local recovery state. It is not signature validation or server authorization. Deleting/revoking a refresh session does not itself immediately expire an issued access JWT.
