# DOSO 0.0.1 机器人 App 产品需求与推进计划

> 状态：首版产品范围已确定；模拟合同、Android BLE discovery 代码门禁与原生 debug 构建已通过
> 客户端版本：`0.0.1`
> 核对日期：2026-08-25
> 证据等级：`SIMULATED + BLE_DISCOVERY_NATIVE_BUILD`；不代表物理扫描、GATT 身份验证、Wi-Fi 配网或机器人固件已经通过

## 1. 产品结论

DOSO 当前首先是一款“机器人所有者 App”，不是一套要求用户理解 GATT、密钥协商、bootloader 或 A/B 分区的工程工具。用户打开 App 后需要完成的核心任务是：

1. 认领属于自己的机器人。
2. 让机器人安全连接网络。
3. 看清机器人是否在线、是否可用、是否需要处理异常。
4. 在满足条件时安全更新固件；失败时知道机器人已经回滚，或需要售后恢复。
5. 在设备可信在线后执行任务、路线、召回和控制，并看到来自机器人的真实结果。

技术协议仍然必要，但它们位于 App、云端和机器人固件之间，不应该成为普通用户的操作步骤。App 只展示用户能理解、能行动的状态。

## 2. 当前问题

当前 App 已有账户、设备绑定、设备页、任务、地图和控制外观，也已经具备安全配网与固件生命周期的纯 TypeScript 合同和离线模拟门禁。但是：

- “序列号 + 绑定码”只完成账户认领，不能让机器人连接 Wi-Fi。
- 设备页只有“连接管理”提示，没有可操作的配网流程。
- 页面只显示固件版本，没有检查更新、资格校验、安装进度、回滚和恢复流程。
- Android 真实设备已进入独立 BLE discovery 页面，原生 debug APK 已编译并在 Android 模拟器启动；但尚未在物理手机读取真实广播，GATT 身份/凭据协议仍待固件侧输入。
- 当前已将无来源遥测改为“待同步”，将任务/路线改为明确的模板预览并关闭执行；App 已建立 fail-closed 命令协调层，但生产 executor 仍为空，真实控制传输、可信 ACK 与数据源仍待建设。

因此更合适的推进方式是：先在 App 中实现明确标注的演示闭环，冻结用户流程和状态语义；随后用相同接口逐步替换为真实 BLE、托管 OTA 作业和机器人固件实现。

## 3. 目标与成功标准

### 3.1 本阶段目标

- 在“我的设备”中提供“网络与配网”和“固件更新”两个设备生命周期入口。
- 用户可以完整操作两个演示流程，并看到准备、进行中、失败、取消、恢复和成功结果。
- 演示流程始终标记“开发演示”，不会连接蓝牙、发送真实 Wi-Fi 密码或更新机器人。
- 真实设备进入 Android BLE discovery：只读取广播并显示“身份未验证”候选，不显示 Wi-Fi 输入，也不自动连接。
- 真实设备不能误用演示 gateway，也不能被客户端伪造成配网或升级成功。
- 绑定、配网、固件升级三个概念和状态彼此独立。
- 页面状态与已实现的安全配网和 OTA 领域合同保持一致，为真机 gateway 留出稳定替换点。

### 3.2 首个切片完成标准

- 从“我的设备”可以进入并走通安全配网演示。
- 从“我的设备”可以进入并走通固件更新演示。
- Wi-Fi 密码仅在输入组件中短暂存在，提交后清空；不进入 reducer、日志、Toast、全局状态或持久化。
- 配网只有在机器人联网确认和云端确认阶段之后才显示“模拟配网完成”。
- OTA 只有 `scheduled` 和 `downloading` 可以取消；进入安装后不能取消。
- OTA 支持成功、自动回滚和需要人工恢复三种结果。
- 没有演示资格的真实设备进入独立 discovery 页面，无法走模拟成功路径；GATT/Wi-Fi 阶段仍不可达。
- 配网与 OTA gateway 行为、静态 UI/wiring guard 均须以各脚本最终 summary 全部通过，并通过 TypeScript 与发布门禁；这不构成组件交互、E2E 或真机证据。

## 4. 用户与角色

### 4.1 P0：机器人所有者

购买或获得机器人后，完成账户认领、网络配置、状态查看和固件更新。需要简单、可靠的引导，不需要理解底层协议。

### 4.2 P1：被授权的操作员

在所有者授权下执行任务、路线和日常操作。默认不能更改所有权、配网信任或固件发布策略。

### 4.3 P1：售后/服务工程师

处理身份验证失败、反复离线、回滚和 `recovery_required`。需要脱敏诊断编号和明确恢复步骤，不能看到 Wi-Fi 密码或私钥。

### 4.4 P0（管理端）：固件发布管理员

创建签名发布、配置兼容型号和最低电量、观察灰度结果并暂停发布。该能力属于后台/服务端，不在 0.0.1 手机 App 首个切片中实现。

## 5. 产品信息架构

配网和 OTA 都属于“我的设备”中的低频设备设置，不新增底部 Tab：

```text
我的设备
├─ 设备状态：在线、电量、固件、同步时间
├─ 网络与配网
│  └─ 安全配网全屏流程
├─ 固件更新
│  └─ 单页状态驱动的 OTA 流程
├─ 绑定/解绑设备
├─ 安全锁
└─ 状态警报
```

概念边界：

- 绑定：证明该机器人属于当前账户。
- 配网：让已认领或演示机器人连接 Wi-Fi。
- 在线：由机器人网关可信上报，App 不能直接修改。
- OTA：由签名发布、托管作业和机器人固件共同执行，App 只发起并展示状态。

## 6. P0 用户故事与验收

### US-PROVISION-01：开始配网

作为机器人所有者，我希望 App 告诉我需要打开机器人、靠近设备并准备 Wi-Fi，以便我知道开始前要做什么。

验收：

- 显示机器人开机、手机蓝牙和 Wi-Fi 可用的准备项。
- 明确说明 App 不会保存 Wi-Fi 密码。
- 演示模式持续显示“开发演示”和不会执行真实硬件操作的说明。

### US-PROVISION-02：发现与确认设备

作为机器人所有者，我希望看到附近找到的 DOSO 机器人及其型号和序列号尾号，以免配错设备。

验收：

- 显示查找状态、找到的设备、型号、序列号尾号和信号提示。
- Android discovery 对真实广播按 ID 去重，显示脱敏标识与 RSSI；无服务 UUID 时所有结果均明确标为“身份未验证”，不自动选择最强设备。
- 身份验证发生在发送 Wi-Fi 凭据之前。
- 真实实现不能只按信号最强自动选择多台设备中的一台。

### US-PROVISION-03：安全提交 Wi-Fi

作为机器人所有者，我希望输入网络名和密码并安全发送，以便机器人联网且密码不会被保存。

验收：

- 输入有可见标签；密码默认隐藏，并有可访问的显示/隐藏控制。
- 提交后立即清空组件中的密码。
- 状态、日志、提示和持久化中不包含密码。
- 页面只展示遮罩后的网络名。

### US-PROVISION-04：理解配网进度

作为机器人所有者，我希望看到机器人正在做什么，以便知道应该等待还是处理问题。

验收顺序：

1. 正在验证机器人身份。
2. 正在安全发送网络信息。
3. 机器人正在连接 Wi-Fi。
4. 正在确认机器人上线。
5. 模拟配网完成或明确失败。

发送凭据完成不能提前显示配网成功。

### US-PROVISION-05：处理失败与取消

作为机器人所有者，我希望错误留在页面并提供下一步，以免短暂 Toast 消失后无从处理。

验收：

- 覆盖未发现、身份失败、密码错误、暂时断连、会话过期、所有权失效和用户取消。
- 错误包含可执行操作，如重新查找、重新输入、重新开始或联系支持。
- 已发送凭据后的取消需要说明机器人可能仍在尝试联网。
- 取消结果常驻页面，不只显示 Toast。

### US-OTA-01：检查是否可以更新

作为机器人所有者，我希望在开始前看到版本、更新内容、预计时长和资格条件，以免在不安全的状态下升级。

验收：

- 演示显示 `0.0.1 → 0.0.2`、更新说明、包大小和预计时长。
- 检查机器人在线、电量至少 40%、没有执行任务。
- 不满足条件时给出具体行动，不创建升级作业。
- 说明安装和重启阶段不能取消且不能关闭电源。

### US-OTA-02：理解更新进度

作为机器人所有者，我希望看到可理解的阶段，以便判断能否离开或取消。

验收顺序：

1. 正在下载更新。
2. 正在校验更新包。
3. 正在安装。
4. 机器人重启中。
5. 正在检查运行状态。
6. 模拟更新完成、已回滚或需要恢复。

只有下载阶段显示百分比；校验、安装、重启和健康检查不虚构精确百分比。

### US-OTA-03：取消更新

作为机器人所有者，我希望在安全阶段取消下载，但不能在可能损坏设备的阶段强制停止。

验收：

- `scheduled`、`downloading` 可取消。
- `verifying` 及之后不提供可用的取消动作。
- 安装后显示“此阶段不能取消，请勿关闭机器人电源”。

### US-OTA-04：理解回滚和恢复

作为机器人所有者，我希望更新失败后知道机器人是否已恢复稳定版本，或是否必须联系支持。

验收：

- 成功：显示目标版本和运行状态正常。
- 自动回滚：显示已恢复到 `0.0.1`，不宣称升级成功。
- 人工恢复：明确要求停止使用并联系 DOSO 支持，提供脱敏诊断编号。
- 页面不暴露签名、密钥、下载 token 或 Wi-Fi 信息。

## 7. 演示与真实设备隔离

首版 UI 使用演示 gateway，并为真实 Android 设备增加独立 discovery adapter，但必须满足：

- 只有型号预览或 `device.is_demo === true` 可创建演示会话。
- 真实设备只可进入 BLE 广播发现；没有 GATT 身份证明时不能连接、输入/写入 Wi-Fi 或进入配网领域成功状态。真实 OTA 仍展示阻塞说明。
- 演示完成文案必须包含“模拟”，不能写成真实配网/升级完成。
- 演示 gateway 不导入 `iot/simulator`；Node 模拟器依赖 `node:crypto`，不得进入 Expo bundle。
- App 不能构造假签名、假设备 ACK 或直接改写数据库中的在线/固件成功状态。
- 未来生产 gateway 与当前演示 gateway 通过同一小接口替换，但凭据、签名和设备状态的权威仍在原生层、服务端和机器人。

## 8. 非功能需求

### 8.1 安全与隐私

- Wi-Fi 密码、短时密钥、下载授权 token 和完整签名不得进入日志、分析、Crash report 或持久化。
- SSID 在设备设置页默认遮罩；支持用户重新输入而不是恢复旧密码。
- 所有成功状态都必须由对应状态机的最终确认产生。
- 生产构建不能通过配置错误意外开启演示 gateway。

### 8.2 可访问性

- 触控目标至少 44×44。
- 输入框有可见标签，状态不只依赖颜色。
- 进度使用 `progressbar` 和可访问值。
- 状态变化使用 live region；需要人工恢复使用更强提醒。
- 字体放大后页面可以滚动，不裁切按钮文字。
- 真机阶段补 VoiceOver、TalkBack、动态字体和对比度验收。

### 8.3 可观测性

生产阶段仅记录：correlation ID、设备/作业 ID、阶段、结构化失败码、耗时和单调序号。所有证据脱敏。

建议事件：

- `provisioning_started/phase_changed/cancelled/failed/succeeded`
- `firmware_check_viewed/eligibility_failed/job_started/phase_changed/cancelled/rolled_back/recovery_required/succeeded`

首个演示切片不接入第三方分析 SDK，只冻结事件名称和禁止字段。

## 9. 分阶段推进计划

### 阶段 A：App 演示闭环（当前）

- 两个设备页入口、两个全屏流程的源码 wiring、演示 gateway、异常与取消状态。
- 配网与 OTA gateway + 静态 UI/wiring guard 均以脚本最终 summary 为准，并执行 TypeScript 与打包检查。
- 明确标注 `SIMULATED`，真实设备保持 `BLOCKED`。

当前证据边界：已验证领域状态与 gateway 行为，并用源码静态 guard 核对 UI 注入和关键文案；尚未用 React Native 组件交互测试或导航 E2E 证明用户能实际走通完整旅程。

完成信号：补齐组件交互/E2E 后，产品人员无需机器人即可评审完整用户旅程、文案和状态边界；这仍不能替代真机验收。

### 阶段 B：Hosted staging

- 配网会话 API、固件可用版本、签名 manifest、OTA 作业、事件、审计和幂等。
- App 从演示 gateway 切换到 staging gateway；退到后台后仍能恢复作业状态。
- 推送更新完成、已回滚和需要恢复。

完成信号：模拟机器人通过托管服务完整跑通，App 重启后状态不丢失。

### 阶段 C：BLE Development Build（原生构建已通过，物理扫描待验收）

- 已选定 `react-native-ble-manager@12.5.1`，加入 Expo config plugin、Android 前台权限/扫描 adapter、候选 UI 与 development build profile。
- 已用 JDK 21 完成 Expo 预构建、四 ABI Gradle debug APK、模拟器安装和 App 启动。下一步在物理 Android 手机验证权限、定位开关、广播扫描、停止、失败码和重试；之后再实现选择、连接、身份验证、分片、超时和断连恢复。iOS 另行推进。
- 冻结 GATT 服务/特征、MTU、分包和安全信道 ADR。

完成信号：两台 Android 和两台 iPhone 在测试 AP 上完成真实配网，密码不落盘，错误路径可复现。

### 阶段 D：真实机器人 OTA

- 固件签名/制品服务、机器人下载器、掉电恢复、A/B 或等价回滚、启动健康证明。
- 执行坏签名、错误型号、低电量、断网、断电、坏镜像和健康超时测试。

完成信号：真实机器人能成功更新，并在故障注入后自动回到已验证版本；失败证明可与 App 作业对齐。

### 阶段 E：可信控制与遥测

- 命令 ACK、任务/路线/召回、在线/电量/故障遥测和通知。
- 删除或明确标注所有演示默认数据。

当前代码已冻结非运动 `diagnostics.health_check` 的生产可替换异步 transport/ingress 合同：transport 的 publish receipt 只代表“接受投递”，绝不代表设备执行成功；ACK/遥测必须在可信 ingress 通过设备绑定、公钥签名、authorization epoch、active boot、TTL/clock skew、遥测单调序列与 ACK 合法状态迁移后，才能由持久化适配器在单事务中重新核对 device/command version、公钥身份、owner、epoch、boot、命令绑定及完整非运动安全合同并提交投影。连接 generation、可重试 store/verifier 故障和不可重试坏帧明确区分，拒绝帧不得改变投影。已解码对象有小帧资源预算；wire bytes 和速率限制属于未来 transport adapter。内存 transport/store 只用于合同测试，未接入 MQTT、mTLS、GATT、Hosted broker 或实体机器人；生产 executor 和所有实体能力门禁继续保持关闭。

完成信号：App 只在机器人 ACK 后显示动作成功，离线和异常状态来自可信上报。

## 10. 依赖与实机验收所需资料

进入真机阶段前需要：

- 至少一台 Android 手机；iOS 发布还需要一台 iPhone。Expo Go 不能代替含 BLE 原生模块的 Development Build。
- 至少一台可重置的机器人主控板/整机，或协议兼容硬件夹具。
- 芯片/模组型号、操作系统/SDK、蓝牙版本和固件仓库访问方式。
- 机器人现有 GATT 服务和特征定义；若尚无，则需要固件工程师共同制定。
- 制造身份来源、设备证书/公钥存储能力、随机数和密码库能力。
- Flash 容量、分区表、bootloader 类型/版本、是否支持 A/B 或等价回滚。
- 可刷写、串口日志和救砖方式，以及允许断电/坏镜像测试的测试设备。
- 2.4 GHz/5 GHz 支持范围、隐藏 SSID 和企业 Wi-Fi 是否属于首发范围。
- 固件制品、签名责任人、测试/生产密钥分离和发布审批流程。

手机只是实机链路的一部分；没有机器人固件/夹具和协议资料，手机只能验证 App 权限与扫描，无法证明安全配网或 OTA 完成。

## 11. P1/P2 产品需求池

### P1

- 首次设置清单：绑定、配网、命名、通知。
- 更换 Wi-Fi、恢复出厂后的重新配置。
- 自动更新开关、更新时间窗和后台作业恢复。

### P2

- 预约更新、分批灰度、失败率自动暂停。
- 售后恢复向导和服务模式。
- 本地局域网离线控制（需要独立威胁模型）。

3. 绑定是否加入 QR 扫码，还是继续以序列号 + 一次性绑定码为主？
4. OTA 默认是手动、自动还是预约窗口？
5. 更新时是否必须在充电座，还是电量阈值即可？
6. 是否要求离线局域网控制和无云配网？
7. `recovery_required` 由用户自助、售后上门还是返厂处理？
8. 现有首页电量、传感器和环境数据在无可信设备时，是全部隐藏、显示“尚未同步”，还是保留明确的演示模式？

## 13. 本阶段非目标

- 不在 Expo Go 中实现真实 BLE。
- 不让手机 App 直接承担固件签名、bootloader 或分区切换。
- 不把 Expo/EAS Update 当作机器人固件 OTA。
- 不用 UI 演示测试替代真实机器人、测试 AP、断电和坏镜像验收。
- 不在 0.0.1 首个切片重做底部导航、视觉系统或多机器人架构。
- 不在 GATT/固件协议尚未确定时引入连接、配对或 characteristic 写入；当前 BLE 依赖只承担前台发现。

## 14. 放行规则

- 当前可分别标记 `SIMULATED PASS`、`BLE DISCOVERY CODE PASS` 与 `BLE DISCOVERY NATIVE BUILD PASS`；原生标记只代表 debug APK 编译/模拟器启动，不得扩写为物理扫描通过。
- `ROBOT-PROVISION-001` 在 Android/iOS 真机、GATT 身份、机器人固件和测试 AP 链路完成前保持 `BLOCKED`。
- `ROBOT-FIRMWARE-001` 在 Hosted OTA、签名/制品服务、机器人 bootloader 和真实 A/B/等价回滚测试完成前保持 `BLOCKED`。
- 任何 P0 真实场景为 `FAIL` 或 `BLOCKED` 时，不能将对应机器人功能描述为已上线。

## 15. 官方技术依据

- Expo Go 不包含任意第三方原生 BLE 实现；加入原生模块后需要 DOSO 自己的 Development Build：[Expo Development Builds](https://docs.expo.dev/develop/development-builds/introduction/)、[自定义原生代码](https://docs.expo.dev/workflow/customizing/)。
- Android 12 及以上的 BLE 扫描与连接需要运行时附近设备权限：[Android Bluetooth permissions](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions)。
- Android 11 及以下直接 BLE 扫描还需要位置权限和已开启的系统定位服务：[AOSP BLE scanning](https://source.android.com/docs/core/connect/bluetooth/ble#ble-scanning)、[Expo Location](https://docs.expo.dev/versions/v57.0.0/sdk/location/#locationhasservicesenabledasync)。
- iOS 真机链路需要按 Core Bluetooth central 流程扫描、连接、发现服务/特征和订阅通知：[Apple Core Bluetooth](https://developer.apple.com/documentation/corebluetooth)。
- 机器人 OTA 的候选镜像确认、健康检查和回滚属于设备 bootloader/固件职责，具体实现取决于选定平台：[ESP-IDF OTA](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/system/ota.html)、[MCUboot design](https://docs.mcuboot.com/design.html)。
