## 在 Figma 中取得 node-id

1. 打开设计文件并点击需要验收的完整页面 Frame，不要选择内部文字、图标或图片图层。
2. 右键选择 **Copy/Paste as → Copy link to selection**；也可以直接复制浏览器地址栏中带 `node-id` 的链接。
3. 链接参数通常显示为 `node-id=139-7397`，仓库文档统一记录为 `139:7397`；两者只是在 URL 中分别使用连字符和冒号。
4. 将新节点同时补入本索引和 `docs/DESIGN_ACCEPTANCE_MATRIX.md`，并核对画板名称、主题和尺寸后再开始截图。

## 三态同尺寸验收流程

1. 分别导出浅色竖屏、深色竖屏和横屏 Frame，保留原始比例；标准尺寸为 `390 × 844`、`390 × 844`、`844 × 390`。
2. 以相同主题、语言、页面状态和系统栏条件启动 App；竖屏截取 `390 × 844`，横屏截取 `844 × 390`。不得用另一状态截图代替，也不得只缩放竖屏布局作为横屏结果。
   Web-only 开发验收页可用 `npm run design-qa:capture -- --stage <page-id> --output <evidence-dir>` 生成精确 viewport 截图；Android 模拟器可用 `npm run design-qa:capture:android -- --serial <adb-serial> --output <evidence-root> --stages <page-id>`。Android 工具要求精确 stage/state 标记、完整 PNG 解码、Metro 端口释放和显示状态恢复复核。两种入口都仅用于当前实现证据，不能替代 Figma 拼图或用于生产路径。
3. 如模拟器物理截图尺寸不同，只做等比例裁切/缩放到上述基准尺寸，不改变画面内容和纵横比。
4. 为每一态生成同尺寸左右对照图：左侧 Figma、右侧 App。建议文件名为 `comparison-light.png`、`comparison-dark.png`、`comparison-landscape.png`。
5. 将原始基准、App 截图、对照图、问题清单和验证输出放入 `artifacts/design-acceptance/<run-id>/<page-id>/`。至少保留 `figma-light.png`、`app-light.png`、`comparison-light.png`、`figma-dark.png`、`app-dark.png`、`comparison-dark.png`、`figma-landscape.png`、`app-landscape.png`、`comparison-landscape.png`、`design-qa.md`、`verification.txt` 和 `evidence.json`。
6. 逐项检查布局、间距、字体、颜色、圆角、图标、安全区、滚动、禁用态、空态和产品数据真实性。存在 P0、P1 或 P2 时继续修复和重拍，不得标为通过。
7. `evidence.json` 必须记录三态 Figma 节点、逐态 PASS、P0/P1/P2 = 0、`typecheck` 与 `npm run test:release-gate:design-audit` 的退出码、证据文件 SHA-256 与当前页面源码依赖 SHA-256。源码依赖变化后，旧证据自动失效，必须按当前源码重拍。历史页面若在全局设计清单接线前确实执行过完整 release gate，可显式记录 `legacy-full`，不得把当前全局失败伪装成通过。
8. 完成单页后更新本索引、验收矩阵、`docs/design/DESIGN_ACCEPTANCE_MANIFEST.json` 和根 `design-qa.md` 的最新运行号与证据目录；运行 `npm run test:design-evidence:audit` 检查已有页面证据。只有清单达到 20/20 后，才运行 `npm run test:design-evidence` 和默认 `npm run test:release-gate` 证明全局完成；单页 audit 不能替代最终 release gate。每份最终页面 `design-qa.md` 以及根验收记录都必须以以下精确文本结束：

```text
final result: passed
```
