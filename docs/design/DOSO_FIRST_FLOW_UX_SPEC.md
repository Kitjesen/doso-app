# DOSO 首组页面：字号统一与交互落地约束

更新：2026-09-08。

> 最新用户反馈：首页「大图 + 列表」视觉已否决，必须回到 Figma 首页结构。下文交互与真实状态守卫仍适用，但不能据此替换原稿的卡片和导航。最新布局边界见 `DOSO_FIGMA_HOME_REFINEMENT.md`。

范围：注册修订、登录、邮箱验证、首页。使用已选的白底 / 克制蓝色 / 石墨黑主操作 / DOSO 机器人设计语言。本组是设计候选与交互规格，不是 App 实现、Figma 同步或发布验收证据；不修改验收清单的通过数。

## 字号与布局优先级

表单统一引用 `DOSO_REGISTRATION_SPEC.md` 的最新版：输入与主要操作 17，标签 15，辅助文字与社交名称 14。标题按角色使用 30/38 与 24/32，首页分区可使用 22/30。

先保证内容和控件可读可点，再分配机器人主视觉高度。小屏、横屏或大字体下缩短装饰、重排和允许滚动，禁止以 10–12 号正文、压缩字宽或关闭字体缩放来挤进一屏。图片区不承载需要动态变化的文字、错误、按钮或遥测。

默认控件至少 48 × 48；输入至少 52 高；CTA 至少 54 高。社交区保持标题到按钮 24、按钮到名称 8。底部导航不得遮盖列表最后一项，键盘不得挡住当前输入与提交动作。

## 当前源码事实（设计依据，不代表所有路径已经实测）

- `src/screens/LoginScreen.tsx` 已有邮箱、密码、显隐、忘记密码、创建账户和社交入口。
- `App.tsx` 的注册结果可能直接建立会话，也可能进入邮箱验证码步骤；不能保证每次注册都显示验证码页。只有服务成功后才显示成功或发送提示。
- `src/screens/EmailOtpScreen.tsx` 已有单一 6 位数字输入、粘贴时数字过滤、one-time-code 属性、60 秒重发倒计时、加载互斥、错误及过期识别。
- 该验证码页的返回回调目前返回登录，并清空待验证上下文，不是「返回注册并保留所有字段」。设计不虚构一个现有实现不存在的返回行为。
- `src/screens/HomeScreen.tsx` 按连接状态显示离线 / 在线；电量缺省为 null，其他遥测为待同步；召回受 `canRecall` 控制，主操作是控制预览。
- `src/components/BottomNav.tsx` 的五个入口依次为首页、地图、任务、分析、我的。新视觉不能擅自更换目的地。

## 页面与交互要求

### 注册

- 用户名 / 邮箱 / 密码保留可见标签；规则不藏在只能记忆的占位文字中。
- 用户名规则保持服务约束；密码显隐不清空输入、不移动到别的字段。
- 失焦或提交后显示字段错误；用户尚未输入时不提前铺满红色提示。错误贴近对应字段，且不只依靠颜色表达。
- 提交中显示明确的进行中文案与指示器，锁定重复提交；失败留在当前页面并保留安全可保留的输入，焦点移到第一个错误。
- 不显示「下一步：邮箱验证」，但不删掉真实验证路径。只有服务返回结果决定下一页面。
- 敏感输入不进入日志、分析事件或持久化草稿；跨页面保留规则在实现时明确，不能把效果图当作已支持草稿恢复。

### 登录

- 顶部「注册」与主操作「登录」分别清晰可点；不在底部再堆一遍注册入口。
- 「忘记密码？」使用 17 号文字与完整 48 高点击区域，放在密码框下方，不挤进小标签角落。
- 邮箱键盘 / 密码管理器语义 / 下一项与完成键正确；空提交与格式错误就地说明。
- 服务拒绝时显示不泄露账户存在性的错误，保持邮箱和可安全保留的当前输入；不得先跳转首页后补报错误。
- 社交入口显示 Apple / 微信 / QQ，尺寸一致。按压、授权中、取消、失败、未就绪分别定义：按压只反馈触控；授权中突出当前提供方并阻止重复提交；取消安静返回；失败说明并可重试；未就绪中性禁用且无障碍报告真实原因，不显示「暂不可用」文案，不强行开启配置。

### 邮箱验证

- 一个可访问的 6 位数字输入，可视觉分段，但不要变成六个独立焦点。支持整串粘贴、删除和系统验证码建议；输入完成后仍由用户点击「验证并继续」，避免误提交。
- 未满 6 位时 CTA 禁用；验证中按钮显示进行中，不能同时重发。只在成功响应后进入下一步骤。
- 邮箱使用脱敏显示；默认画面中的 `example.invalid` 仅为提案占位，不是真实收件人，也不证明邮件发送。
- 明确的错误恢复：错误码可修改后重试；过期时给出「验证码已过期，请重新获取」并允许重发；网络失败不伪装成验证码错误。
- 重发成功才清空旧码并重启计时，失败保留可恢复状态。后台切回后的倒计时应按截止时间恢复，不能把本地逐秒计时假定为已经支持此能力；这是后续实现检查项。
- 顶部明确「返回登录」，避免普通返回箭头让用户误以为回到已填注册表单；移除底部重复的同目的地入口。进行中返回行为须与取消 / 请求失效保护一致，不能重复触发。
- 可以加一句检查垃圾邮件文件夹的短提示；不加入没有实现的「打开邮箱」「换邮箱」或虚构自动填充按钮。

### 首页

- 首屏只强调当前机器人与一个主要动作，保留地图、任务、分析、我的的导航结构。
- 同一首页只在设备卡展示一次机器人。召回是动作入口，不再重复展示产品缩略图；这是减少重复信息，不是缩小主图。
- 离线明确显示「离线」，未知电量为「—」，不能以 0%、随机电量、正常遥测或虚构活动填满页面。
- 「控制预览」必须与「实际操控」区分，说明仅浏览界面、不发送运动指令；连接设备并不自动意味着运动协议已经接通。
- 巡航模板 / 任务模板 / 设备安全保留 Figma 三张并排、带凹口的异形卡片；整张卡可点，箭头与卡片为同一动作而非重复无障碍焦点，按压反馈一致。不能改成纵向列表，也不能把预览模板标成启动巡逻或执行任务。
- 召回只有受信执行能力成立才可执行。首页可以降低不可执行动作的视觉优先级，但不能在视觉更新中删掉能力守卫或伪造成功。
- 导航选中态不只靠变色：保留统一容器、图标形态与可访问的 selected 属性；五项触控区域一致，点击后标题与内容同步。
