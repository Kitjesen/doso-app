## 优先推进

1. [ ] **停止与链路状态。** 控制页显示连接、控制权、停止请求与确认结果，断链/超时清晰告警；设计机器人侧失联停止与恢复验收。当前 `src/features/control/brainstemControlSession.ts` 将停止就绪与连接及活动租约绑定，不等同于独立机器人级急停。山猫软急停会使其机器人趴下，不代表 DOSO 的停止会执行相同动作；具体行为须与实际 Brainstem 契约和硬件停止回执核对。
2. [ ] **关节与故障。** 基于真实来源展示 16 关节的在线/故障、角度、速度、力矩与温度；按四腿分组并提供可展开详情。当前 `src/screens/JointStatusScreen.tsx` 已有列表和字段，`useBrainstemTelemetry.ts` 对四项数据约每 5 秒查询一次，不是高频曲线。要分析 hip 震荡，还需设备提供带时间戳的目标角与实际角，校对频率、单位和时间对齐；温度/驱动器分类及阈值使用本机真实数据。
   - [x] 本地 App 完成 16 项总览、四腿详情、原始错误码、缺失/离线值及静态机型图；G20 使用明确标注的离线模拟数据验证 16 项与详情滚动。
   - [x] 本地 Brainstem 将 `ListenJoint` 硬件报告的编号转换为协议 Matrix4 顺序；16 项映射及无效 ID 离线测试通过，尚未部署。
   - [ ] 补齐稳定的错误码合同、分级异常/事件与恢复状态，以及带采样时间的真实目标与实际值；完成真实机器狗和 G20 端到端验收。
3. [ ] **摄像头和视图。** 先接入经核验的单路视频；多源可用后提供镜头选择、主画面/小窗互换、单/双画面；视频加点云单独作为布局选项。拍照和录像按能力与权限启用，状态、断流和旧帧必须可辨。当前 DOSO 有 `ControlVideoSurface` 容器，但缺真实接收器/解码器；LingTu 源码已有 WHEP 视频和点云相关链路，目标机器部署状态待核验。详见 `designs/control-console/camera-view-design.md`。
4. [ ] **链路质量。** 区分 G20 的 Wi-Fi RSSI、App 到机器狗的往返时间/超时、图传状态和机器人在线状态；标明数据来源与更新时间。`useControllerWifiSignal.ts` 是 G20 侧 RSSI，不能当作机器人端接收质量或端到端延迟。
5. [ ] **G20 绑定与快捷键。** 完成两杆通道、方向、回中与稳定性校验后，允许通过用户已验证的按键绑定停止、站坐和镜头切换等；避免把山猫的物理按键位置或通道号假定为 G20 的映射。`G20InputPanel.tsx` 现有六种动作映射，摄像头切换不在其中。
6. [ ] **模式与速度。** 在 UI 中区分手动/辅助/导航等操作方式、平地/楼梯等策略、实际姿态及速度限制；仅展示设备真实支持且通过准入的选项。速度限制和行为由机器人端最终约束，不照搬山猫参数；实际速度与指令速度需分别标记。
7. [ ] **电池与其他设备能力。** 仅从真实 BMS 展示电量百分比；现有 Brainstem 直连路径显示总线电压，不把电压推算成剩余百分比。双电池、照明灯、回充、传感器管理等按实际能力再开放。

建议顺序：先把停止和链路稳定性验收完成，再做关节/故障可视化；随后接入单路视频、按实际硬件扩展多视角与点云，最后补快捷键及条件能力。每项都分别记录电脑模拟结果、G20 原生结果和机器狗真实结果。
