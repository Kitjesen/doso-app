# DOSO 字体与提示文案规范

2026-10-11，先完成统一字级与路线页修正；随后按用户明确要求，实际替换为 MiSans。此前“保持系统字体”的建议已由本次字体替换更新，字号与行高方案不变。

## 当前字库接入

- 页面正文、标题、按钮与输入框通过 `components/AppText.tsx` 使用 MiSans，覆盖 App、QA 与离线预览入口。没有全局猴子补丁，不改变图标字体；BLE 诊断显式 monospace 保留。
- 原始静态 OTF：Regular、Medium、Demibold、Bold。分别用于语义字重 400、500、600、700 及以上；原文件 OS/2 weightClass 实际是 330、380、450、630，不能把语义值说成文件元数据。通过独立字族别名选择真实字形，再设置 normal，避免系统叠加合成粗体。
- 四份原文件合计 **26,291,632 bytes（约 25.07 MiB，未压缩）**，从[小米官方字体包](https://hyperos.mi.com/font-download/MiSans.zip)提取，已核对 ZIP CRC32，并记录 SHA-256。没有子集化、转换、重命名字体内部信息或修改字形。
- 官方许可与来源信息保存在 `assets/fonts/`，完整中英协议同时以文本随 App 打包。“我的”页面底部可展开“界面字体 · MiSans”查看版权与许可，不需要联网。
- 沿用已有 expo-font，在两个根入口加载本地静态资源。准备中短暂显示进度；加载失败或超过 5 秒先回退系统字体，不永久阻断认证。后续加载完成可以更新字体，但不重挂账户页面或重发请求。
- [官方许可](https://hyperos.mi.com/font-download/MiSans%E5%AD%97%E4%BD%93%E7%9F%A5%E8%AF%86%E4%BA%A7%E6%9D%83%E8%AE%B8%E5%8F%AF%E5%8D%8F%E8%AE%AE.pdf)要求软件中署名、保留协议与版权，禁止改编及单独分发字库；本项目将其作为 App 组成部分使用。

## 字体选择依据

- iOS：采用系统字体 API 的默认字体，由系统处理不同书写系统。SF Pro 不是完整中文字库，中文使用系统提供的中文字体；不将 Apple 字体文件复制打包到 Android 或 App 资源中。[Apple Fonts](https://developer.apple.com/documentation/technologyoverviews/fonts)、[系统字体列表](https://developer.apple.com/fonts/system-fonts/)
- Android：Material 3 的默认标尺以 Roboto 为例，中文由系统的 CJK 字体回退处理，不能保证各厂商手机字形完全一致。[Material 3 Typography](https://developer.android.com/develop/ui/compose/designsystems/material3#typography)
- 真实产品可以使用定制字体：Spotify 官方披露 Spotify Mix 用于 App 与桌面体验，首轮覆盖拉丁书写语言和越南语。这不代表它能解决 DOSO 的中文排版。[Spotify Mix](https://newsroom.spotify.com/2024-05-22/introducing-spotify-mix-our-new-and-exclusive-font/)
- 品牌表达与正文可以分工：IBM 的开发者品牌系统分别规定 Plex Mono 和 Plex Sans 的角色，不必把强个性的展示字用于整页正文。[IBM Typography](https://www.ibm.com/brand/experience-guides/developer/brand/typography/)
- Noto Sans SC 是已调查过的备选；本次用户要求实际改变字形，因此选择 MiSans 而非继续使用平台系统字库。

## DOSO 字级

定义在 `src/typography.ts`，属于产品设计选择，不是逐项照搬平台默认值。

| 角色 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 24 / 32 | 600 |
| 区块标题 | 18 / 26 | 600 |
| 卡片标题 | 16 / 24 | 600 |
| 正文 | 16 / 24 | 400 |
| 次要说明 | 14 / 22 | 400 |
| 短状态、日期 | 12 / 18 | 400 |
| 标签 | 15 / 22 | 500 |
| 主按钮 | 17 / 24 | 600 |

- 中文不增加负字距，不以过浅颜色或细小字体隐藏拥挤。
- 字号与行高作为一组使用；选中态改变边框、底色、图标，不跳字号。
- 保留系统字体缩放。卡片以自然高度和最小高度容纳内容，不通过固定高度或截断标题掩盖问题。
- 不使用全局 Text 默认属性覆写，避免第三方组件和关键数据文本发生未验证的变化。

## 提示文案取舍

- 同一事实只解释一次：模板预览、元数据未同步等信息不在每张卡片反复占用三四行。
- 保留决定行为的状态：离线、权限不足、按钮禁用原因、请求失败、破坏性操作后果不能删除。
- 把详细前置条件放进可展开的说明；默认界面仍有清晰的只读/不可执行提示。
- 内部术语优先改成用户能理解的结果，不修改底层真实能力与控制策略。
- 开发 QA 壳提示和用户界面分开评估；不删除测试隔离声明来伪装真实服务已接入。

## 本轮实际采用范围

字级 token 已采用：路线页与共享 AppHeader。共享 Header 会影响使用它的主页面。

字体家族已接入所有业务 Text/TextInput；认证、首页卡片、任务、分析、个人页和控制页原有独立字号仍需逐页规范，未宣称全量字级与所有设备布局验收通过。既有历史原生截图和 Figma 通过记录不自动继承为新字体证据。

## 其他页面的文案待办（只审计，未在本轮改动）

1. 任务页：模板选中、日期切换与汇总中重复声明只读。建议只保留一个预览标记，操作反馈仅说明当前选择；未知任务记录不能写成确定没有任务。
2. 分析页：同步状态、数据来源与底部说明重复。合并空态，但仍明确历史数据服务尚未接入，不能改成“连接后即可查看”。
3. 控制页：合并重复的连接/遥测状态，工程细节按需展开。必须继续区分未连接、权限、安全锁和执行能力缺失。
4. 个人页：审计“连接管理”与“网络与配网”的重复入口，两者当前调用同一配网处理器；合并前需保留BLE扫描与配网的能力区别。
5. 首页：保留“控制预览”和各未知指标的“待同步”，它们直接影响用户对设备状态和危险动作的判断。
