## 首版范围

- 从 LingTu 已保存的完整地图导出，不接受把单张图片、单份点云或 App 示例路线冒充完整巡检地图。
- 每次上传形成一个新的不可变地图版本，不覆盖旧云文件；只上传用户本次选择的地图。
- 云地图目录只需用户登录和互联网，不依赖机器狗当前在线；向目标狗发起新下载要求目标可达并有本次用户授权。首版不增加任意时长的离线预约下载。
- 文件传输用 HTTPS，MQTT 只传操作 ID、地图版本和操作结果。地图不会穿过普通遥测消息或数据库大字段。
- 导入为新的本地地图 ID，下载完成、导入完成、导航激活分别显示。
- 地图分享、跨账户转交、在线编辑、地图合并、自动备份和自动激活不进入首版。

## 用户流程

### 上传

1. App 读取所选设备的真实本地地图目录。
2. 用户选择地图并点击上传，看到地图名称、版本和传输网络提示。若大小尚未导出得知，显示“准备文件”，不估造进度。
3. 设备调用既有 `export_map_package`，为本次任务生成唯一导出目录。导出时已有源地图锁；导出副本与后续源地图修改分离。
4. 从导出的实际副本读取源 map_id、content_epoch 和元数据，形成标准归档；计算归档大小和 SHA-256。
5. 后端校验账户、设备归属与本次上传授权，创建地图版本和仅供该对象使用的上传能力。
6. 设备通过 HTTPS 上传，支持失败后针对同一授权任务续传。校验完整文件后，云目录才标为 ready。

### 下载与导入

1. 用户在云目录选择 ready 版本，再选择目标机器狗。
2. 后端核对地图固定所有者、目标设备当前归属和本次授权，创建传输任务。
3. 设备收到任务 ID 后，通过鉴权接口获取该任务的受限下载信息，不接受任意外部 URL。
4. 下载到本次任务的临时目录；完成大小与 SHA-256 校验、归档路径检查后解包到 LingTu import exchange。
5. 调用既有 `import_map_package`，使用新的本地 map_id，不使用当前活动地图名。
6. 设备返回实际导入后的本地 map_id/content_epoch。App 显示“已导入，未使用”。

### 单独使用

用户再次选择“使用此地图”后，调用已有 ProductControl 流程；由本地地图与定位系统检查可用性。只有本地激活与定位条件满足才显示相应成功状态。下载/导入程序没有运动权限，不自行修改活动地图指针。

## 数据与文件落点

| 内容 | 位置 |
| --- | --- |
| 账号、设备归属 | 现有 Supabase Auth/PostgreSQL |
| 地图目录和版本元数据 | 同一个 PostgreSQL，独立 `device_map_versions` 候选表 |
| 地图包字节 | 用户已选私有对象存储；首选与现有 ECS 同地域的阿里云 OSS 私有 bucket，尚未开通 |
| 传输进度与结果 | 有界任务记录，关联版本和目标设备；不记录文件 URL 中的授权参数 |
| 下载与导入后的地图 | 目标机器狗的本地 exchange 和 MapStore |

森哥已选择私有对象存储。首选上海 OSS，与现有 ECS 同地域；这是接入方案，不是已采购或已部署服务。ECS 保留 MQTT、网关与业务入口，机器狗通过 HTTPS 直接上传/下载对象，App 不代理完整地图字节。

OSS 接入按以下边界实现：bucket 私有；后端持有仅限地图 bucket 的权限；设备不保存长期 OSS AccessKey。上传由后端创建 multipart 任务，为本次对象的指定分片签发受限上传能力；后端负责完成 multipart、验证文件并提交 ready。设备不取得通用 PutObject、覆盖其他对象或列出整个 bucket 的权限。每个云地图版本使用独立 key，完成后不再向该 key 签发上传能力。下载仅对已授权 ready 版本签发临时能力；新连接/续传时重新核对任务和权限。断点记录只用于同一对象版本的续传，不绕过新的授权核对。

已查看的车库地图仅 `map.pcd` 与 `octomap.ot` 就约 662 MB，未包含全部 patches。不能使用现有 3 MiB 的头像 bucket；本地 Storage 样例关闭且限制 50 MiB，不能认为现有配置可直接接入。尚未上传、压缩或复制这份真实地图。

地图大包传输按用户网络选择进行；计量/蜂窝网络需明确允许。Wi-Fi 接口可能连接 5G 路由器，不能仅凭接口类型认定免费流量。

## 地图格式与最小合同

原生格式保持 `lingtu-map-package-v1`，原包由 `package_manifest.txt` 和 `map/` 完整目录组成。原 manifest 严格为 format/map_id/schema 三个字段，不往里面加入云字段。

云版本记录最少包含：

- 不可变版本 `id`，固定创建账户 `owner_id`，来源 `device_id`，用户可读名称。
- 原生 format/schema、源 map_id/content_epoch、已知 frame_id（无来源则为空）。
- 服务端分配且不可覆盖的 object key、实际文件大小、SHA-256。
- uploading/ready/failed、创建与完成时间；准备上传时的设备授权代次和请求幂等标识。

导入后原生 MapStore 分配新 content_epoch，不能把源 epoch 当成目标 epoch。设备换主人不自动转移旧地图所有权。

业务侧最小 API 操作：

| 操作 | 接受内容 | 返回 / 行为 |
| --- | --- | --- |
| 列目录 | 当前用户会话，可选筛选 | 本用户可见的版本与上传状态 |
| 准备上传 | 来源设备、导出副本元数据、本次用户操作 | 版本 ID、传输任务、该对象的上传能力 |
| 完成上传 | 传输任务 ID | 可信文件校验与事务复核通过后转为 ready；App不可自行设置ready |
| 发起下载 | ready 版本 ID、目标设备 ID | 有权限且目标可达时创建下载任务 |
| 获取进度 / 取消 | 任务 ID | 展示实际字节和阶段，取消后不自动重新开传 |

这里定义业务职责，不抢先发布另一套正式 MQTT 字段。Rust `shared` 与 `CONTRACT.md` 是运行消息的唯一真源，由 RM500U-CNV 主线维护；本聊天按合同实现 App/DB。

地图任务结果至少区分“传输完成”“校验完成”“导入完成”，回执包含本地导入身份。网络中断可在授权仍有效时续传，不能把半文件或仅客户端声明的 checksum 标为 ready。已有临时下载能力的过期/撤销边界必须由选定服务说明，不能声称取消能撤回已离开网络的数据。

大地图传输使用异步任务：接口接纳后返回 transferId，App 通过任务进度获知结果。不能复用当前 status.read 的八秒 HTTP 等待来承载整包传输，也不能把设备“已接收下载任务”的 ACK 显示为“已下载”。进度只使用实际传输字节；校验、导入和激活分别是后续阶段。

| 阶段 | 本聊天 | RM500U-CNV 主线 | 完成证据 |

## 当前依赖和限制

- 用户已选定私有对象存储路线；当前按上海 OSS 设计，bucket名称、实际配额、费用与权限在开通前核对。本轮不创建bucket、不购买服务、不更改ECS。
- 当前账号数据库有 `devices_one_physical_per_owner_idx`：一账户只能同时绑定一台真机。首个地图闭环以一台已绑定设备验证；真正的多台目标选择依赖设备管理解除该约束并同步绑定RPC/App选择逻辑，这作为独立变更，不在地图补丁中悄悄删除限制。
- 真机暂不开机；没有导出、上传、下载或激活真实地图。
- Docker/Supabase完整本地Storage环境目前未运行。原生PostgreSQL可用于RLS/事务检查，但不能代替真实文件字节传输测试。
- 原生导入仍会替换同名非活动地图，现有接口保留此行为；云下载始终选新ID。本轮已补活动图保护，不扩大到通用地图迁移框架。
