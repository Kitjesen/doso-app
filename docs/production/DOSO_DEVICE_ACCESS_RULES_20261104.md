# DOSO 机器狗连接与使用规则

版本 1.0 · 2026 年 11 月 4 日 · 产品规则存档

适用范围：DOSO App、本地 SDK、机器狗运行时与远程状态服务。依据森哥确认的方向，借鉴宇树将 App 绑定与本地 SDK 分开的方式。本文规定 DOSO 的产品行为，不代表宇树内部架构，也不作为量产或真机验收证明。

## 1. 设备归属、连接和控制分别确认

设备归属回答“云端由谁管理这台机器狗”；连接回答“当前终端能否与它通信”；控制权回答“当前谁可以发出运动指令”。三者分别判断，不使用一个“已绑定”标志代替全部状态。

| 入口 | 用途与前提 | 账号与归属规则 |
| --- | --- | --- |
| 本地使用 / SDK | 同一局域网、有线或其他已支持的本地网络；通过设备本地授权 | 不以云端认领或公网登录成功为前提；不改变 owner |
| 云端远程管理 | 设备能访问互联网，用户账号具有设备访问权限 | 每台设备由用户主动开启，默认关闭 |
| 绑定到账号 | 用户明确建立或移交云端管理归属 | 后端验证授权，原子确认归属；单纯发现设备不等于绑定 |

本地路径：App 或 SDK → 本地网络 → 机器狗授权与控制服务。

远程状态路径：App → 业务服务 → MQTT 网关 → 机器狗状态 Agent。连接恢复不会自动产生运动指令。

## 2. 必须保持的规则

- 不把认领码作为每次连接、借用或二次开发的门槛。
- 本地通信仍需要有效的设备授权；处于同一 Wi-Fi 不等于自动获得控制权。
- 正式 App 使用已支持的本地证书连接；工程测试的明文局域网能力继续受原生安装包限制。
- 读取到状态不代表取得运动控制权。申请控制、使能和动作执行仍经过既有安全链路。
- 一台设备可以被多个获准终端观察；运动控制保持现有单一租约和现场遥控优先级。
- 进入后台、退出本地使用或连接中断时，取消未完成操作并按安全链路停止、释放本次控制；无法确认停止时保留明确提示，恢复前台不自动恢复运动。
- 所有云端数据访问继续核对用户权限。本地授权不自动授予云端地图、视频或历史记录访问权。

## 3. 首次连接、借用与转交

| 场景 | 用户操作 | 系统处理 |
| --- | --- | --- |
| 首次本地使用 | 选择“本地使用”，连接目标设备并取得本地授权 | 建立本次独立会话，不写云端 owner，不自动申请运动权限 |
| 首次绑定到账号 | 确认目标设备，明确提交绑定 | 验证有效凭证及设备条件，防止并发抢占和误绑定 |
| 临时借给他人 | 借用者使用获准的本地连接 | 原归属保持；归还后结束本次会话，按本地授权机制撤销该终端权限 |
| 借用者需要远程访问 | 所有者明确授予相应云端权限 | 属于共享功能，不转移 owner；共享实现前不向非所有者开放 |
| 换手机或遥控器 | 恢复已有账号，或为新终端取得本地授权 | 不重复认领机器狗；每个终端使用自己的凭据 |
| 转售或永久转交 | 明确解除旧归属，再由新用户绑定 | 撤销旧云端许可，远程管理恢复默认关闭；永久设备 ID 不变 |

借出机器狗不要求交出账号密码或复制原终端私钥。退出会话负责结束本次控制；长期本地凭据的撤销仍由设备授权机制执行，不能把退出 App 写成已经吊销证书。

## 4. 认领凭证与近场确认

首次云端绑定必须有明确授权依据。认领码是其中一种实现方式，可以封装在受保护二维码中，由 App 处理，普通用户无需手输。它不是设备 ID，也不是 MQTT 证书。

“发现附近机器人 → 确认目标 → 明确绑定”是交互方向。公开设备 ID、BLE 广播名称、能 ping 通、IP 相同或 CSR 持钥证明，都不能单独证明用户有权取得云端归属。

当前 DOSO 已有专属二维码解析和显式确认流程；BLE 发现与真实设备身份验证尚未形成完整的首次绑定链路。现有归属后的身份验证入口不能直接冒充首次近场认领。在完整证明链路验收前，不因简化交互而删除后端归属校验。

首版先完成本地使用和远程状态。工厂制码、多人云端共享、售后移交不作为本地连接和 SDK 使用的前置条件。

## 5. 数据放在哪里，由谁决定上传

| 数据或功能 | 默认位置 | 上云或使用条件 |
| --- | --- | --- |
| 平衡、步态、避障、急停 | 机器狗本地 | 由本地控制与安全服务负责；云端不可绕过 |
| 原始相机、雷达、IMU、电机高频数据 | 机器狗本地 | 不因联网或账号绑定自动持续上传 |
| 本地地图与导航 | 机器狗本地 | 用户选择上传；云端保存目录与私有文件 |
| 运行状态与关键故障 | 默认不持续上云 | 用户为该设备开启远程管理后上报，显示采集时间 |
| 实时视频 | 默认不开启远程推流、不录像 | 用户主动观看才建立连接；网络需要时可中转 |
| 照片、录像、详细日志 | 默认本地 | 用户选择保存到云端或主动提交售后时处理 |
| 账号、设备归属与访问权限 | 业务云端 | 仅服务于对应账号和设备的管理功能 |

电量只显示真实来源提供的数值。当前远程状态协议尚未接入电量百分比，不得用电机电压、网络在线或示例数值推算并冒充已测电量。

## 6. 远程管理和网络中断

- 每台设备独立开关，默认关闭。登录、绑定、打开页面及重新联网都不自动开启。
- 用户开启后，后台按既有许可机制续期；App 退出前台不改变用户已经保存的选择。
- 用户关闭后，云端停止接受后续状态；设备确认停止前，界面明确显示等待确认。设备失联时由短期许可到期停采。
- 云端无新数据时显示最后采集时间和过期状态，不把网络中断直接解释为机器狗关机。
- Wi-Fi、有线和 4G/5G 都只是网络承载方式；没有互联网时不能远程上云，已授权本地能力仍可按本地规则使用。
- 地图上传、视频观看、任务下发分别由用户选择，远程状态开关不联动开启这些功能。

地图下载流程为：用户选择地图 → 指定机器狗下载 → 检查完整性并导入 → 用户另行选择是否使用。下载或导入完成不能被表述为已经切换导航地图。

## 7. 当前实现与验收边界

| 项目 | 当前状态 | 后续验收 |
| --- | --- | --- |
| 独立“本地使用”入口 | 源码与行为测试已完成；复用本地授权、控制会话和界面 | 新 App 构建安装及真机授权连接尚未验收 |
| 本地读状态与安全控制链 | 已有实现；本地读状态曾在真实机器狗验证 | 独立本地入口的完整真机控制流程尚未验收 |
| 账号绑定 | 已有扫码、确认及后端归属事务代码 | 真机身份匹配与近场首次绑定仍待接通 |
| 用户远程状态开关 | 已有业务接口、通信程序和分层测试 | 真实狗端持续上报到实际 App 的完整链路仍待验收 |
| 云端多人共享 | 规则已区分，尚未实现 | 按真实需求另行实现与验证，不能冒用所有者账号 |
| 地图与视频 | 分别保留用户选择和独立权限边界 | 不作为本轮状态连接已完成的证明 |

首个端到端完成标准：一台真实机器狗、一个明确授权的账号。用户开启远程管理后，实际 App 持续显示真实状态及采集时间；关闭后停止采集；断线和恢复显示准确。测试数据和本地模拟必须明确标识。

本轮本地使用与安全生命周期回归 108 项、连接/扫码/身份页检查 79 项通过，完整 TypeScript 检查与独立代码复审通过。测试包含真实控制会话类，网络和硬件由明确的测试替身提供。代码检查和本地自动化测试不能代替实际安装包与机器狗验收。
