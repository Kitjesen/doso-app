## 2026-10-26 候选技术路线

让 App 与机器狗通过 WebRTC 统一传输实时信息，机器狗内部继续用现有 gRPC 接入 Brainstem。当前先把已写好的 gRPC 连接验通，再逐项迁移。

目标链路：G20 上的 DOSO App，经 WebRTC 连接机器狗 RTC 接入进程；该进程通过本机 gRPC 调用 Brainstem；现有控制仲裁和电机执行规则保持。视频与音频使用媒体轨道，点云、状态和控制使用经过正式设计的数据通道。

本机 gRPC 这段负责 Brainstem 的控制与状态。相机、音频和点云的真实数据源通过各自采集/感知管线接入 RTC 进程，不要求将媒体搬进 Brainstem 运动控制循环。

BLE 负责首次配网，后续状态和控制继续走 Wi-Fi/IP。账号登录、云端设备管理和升级下载使用 HTTPS。当前 LAN 开发模式仅用于受控局域网联调，不作为量产或公网认证设计。

RTC 接入不是可信运动指令的无条件代理。本机 gRPC 仍须执行经审查的调用者和租约约束，不允许普通本机进程绕过仲裁；WebRTC 会话身份、信令和控制授权须在迁移设计阶段明确。任何时刻只有一个运动命令出口，不在运动中自动回退协议或重放旧指令。

## App 当前已接的四类查询

| RPC | App 已解析内容 | 发布前限制 |
| --- | --- | --- |
| GetControlStatus | 状态机阶段、动作过渡、电机输出使能、控制来源、严重故障、租约是否有效、行走就绪 | 连接和状态必须来自同一设备/会话且有效；连接成功不授予控制权 |
| GetProfile | 当前策略、可选策略、策略描述 | 服务端目录不是用户发布目录；34 项历史目录包含实验条目，不全部开放 |
| GetVoltage | 母线电压数组 | 超时或零值不显示为有效电压；不得直接换算电池 SOC |
| GetMotorStatus | ID、在线、状态码、温度、位置、角速度、力矩、错误码 | 离线或缺报告的数值回落不能当健康数据；温度/力矩等仍需逐字段真机核对 |

GetMotorStatus.voltage 当前服务端固定为零。App 电压显示应使用 GetVoltage 对齐电机 ID，不能把该占位字段作为真实供电测量。

当前 GetVoltage 的零值可能来自超时，现有返回合同尚不足以把占位、超时和真实测量为零全部区分。首批显示规则是未知/不可用，并记录可获得的诊断来源；完整发布前补齐有效性与超时语义，不把零值或缺失值推导为健康、电量或实际欠压结论。

## Brainstem 还有哪些已有接口可接

以下结论来自当前本地实现，不证明该版本已部署到机器狗或被 App 使用。

| 接口 | 已有内容 | App/发布计划 |
| --- | --- | --- |
| GetStartTime | UTC 启动时间 | 后续设备诊断，不作为设备在线证明 |
| GetParams | 配置机型与站立关节位 | 工程诊断优先，避免把控制参数直接开放为用户设置 |
| GetCmsState | FSM、过渡类型和动作名称 | 结合控制状态统一呈现，避免两份状态互相冲突 |
| ListenCmsState | 首帧与后续 FSM 状态 | 作为后续运行状态推送来源之一 |
| ListenImu | 角速度、四元数、加速度和时间戳，真机入口有 Hi91 接线 | 后续姿态/诊断；坐标、单位、时间和新鲜度验收后发布 |
| ListenJoint | 关节 ID、位置、角速度、力矩、状态码和时间戳，真机入口有 CAN 报告接线 | 后续关节快照，限频推送 |
| ListenHistory | 推理观测、目标关节和增益 | 仅工程调试，首批用户版本不开放整流 |

GetSpeedMode 和 ListGestures 虽有协议声明，但当前实现仍为 unimplemented，不列为可用查询。

## 首批状态范围与后置范围

首批指计划中的受控测试包，所有项目均须通过对应 G20/机器狗实测，不表示当前已经可公开发布。

| 内容 | 计划 |
| --- | --- |
| 控制/姿态阶段、电机输出、控制权、故障、行走就绪 | 首批，来源有效且断线/过期状态明确 |
| 当前策略与可选策略 | 首批，仅展示该机器狗已实测放行的策略或模式 |
| 母线电压 | 首批，有效值显示 V，超时/零值显示未知 |
| 关节在线、错误码、温度、位置、角速度、力矩 | 首批诊断候选，逐字段验真；未通过的字段保留未知 |
| IMU 姿态/角速度/加速度 | 后续接入已有流，完成坐标、单位和采集时间验证后发布 |
| 电池 SOC/剩余续航、机身实测速度、RSSI、里程 | 后置，当前缺真实来源或 App 接线；先补来源再显示 |
| 视频、音频、点云 | 后续真实源与 RTC 链路逐项验收；不得用占位画面或合成数据冒充 |

电压不等于 SOC，关节角速度不等于机身速度，Walk 的目标速度只能标为指令速度。当前 IMU 加速度未证明已消除重力，不能直接积分后当作可信速度或里程。

## 从查询到实时推送

本表是目标消息计划，不是已上线的主题或冻结协议。

| 发布内容 | 数据来源 | 计划发布方式 |
| --- | --- | --- |
| 运行状态与策略 | ListenCmsState、GetControlStatus、GetProfile | 新连接首帧和变化更新；另有活性/失效检测 |
| 关节状态 | ListenJoint、GetMotorStatus | 有界快照、限频；防止调试/报告流挤占控制 |
| 母线电压 | GetVoltage | 低频读取后推送，不因订阅存在而重复高频请求硬件 |
| IMU | ListenImu | 按展示需求限频，保留原始采集时间与坐标定义 |
| 动作结果 | 控制请求回执与状态确认 | 绑定请求/会话/序号，区分提交、接受、执行中和结果确认 |

每条状态至少包含设备标识、连接代次、序号、采集时间、明确单位和有效状态。断线/过期后不能保留假在线或把最后一帧当当前值。对增量协议须定义丢包后的快照恢复。

视频和音频走媒体轨道；点云必须定义帧号、采集时间、坐标系、压缩/分片上限及过期帧丢弃。DataChannel 分开不代表带宽/CPU隔离，必须有队列上限、限流和拥塞降级。

状态频率、视频/点云预算、端到端延迟、ACK 和本地失联停止阈值在实现前列为验收指标，经真实 G20 和机器人量测后冻结，不在本计划虚构已达标数字。

## 分阶段推进与发布门槛

| 阶段 | 交付范围 | 通过条件 |
| --- | --- | --- |
| P0 gRPC 只读基线 | 当前新包与真实机器人四类查询、字段来源 | APK/服务版本与哈希绑定；真实读值；断网、重连、前后台和过期均正确 |
| P1 受控控制测试包 | 触屏/实体输入、站坐、电机操作、策略切换 | 现场保护和具体动作授权；独立急停现场有效，控制权独占、实体控制优先级、租约、序号/ACK、旧输入丢弃与失联停止逐项验证；重连不得自动续动 |
| P2 WebRTC 只读测试包 | 视频与状态双端闭环 | 真实来源、会话目标、画面/状态新鲜度；拥塞、后台、重连与资源测量通过 |
| P3 实时能力分项发布 | 音频、点云、RTC 控制分别验收 | 硬件源和播放/渲染闭环；媒体满载下控制时效与失联保护；切换前失效旧控制会话 |

P3 是多项独立验收，不要求音频、点云和控制同一次一起开放。RTC 控制验收通过后，App 日常控制退出外部 gRPC 路径；机器狗本机 gRPC 保留。BLE 配网独立推进，不阻塞当前 IP 基线。

辅助遥测的 5 秒刷新/15 秒过期仅用于展示，不能作为控制保护时限。P1/P3 必须独立量测输入到执行路径、租约失效和机器人本地停止行为；无线停止包可能无法送达，不能以 App 发送成功替代独立急停与本地兜底。RTC 迁移沿用同一套控制权和安全语义。

受控测试包不等于公开发布。公开发布还需真实登录/注册、设备归属与访问权限、隐私和账户删除、安装升级/兼容性，以及机器人安全验收。当前继续 NO-GO。按证据门推进，不编造发布时间，不由本计划授权生产数据库、网络权限或真实运动变更。
