# 位置历史与实时轨迹

2026-11-12本地源码合同候选，尚未部署。复用ThingsBoard已有历史，原始定位及报告时间各自保留。历史查询与地图展示为只读功能。

`GET /functions/v1/remote-history?deviceId=<UUID>&startTs=<ms>&endTs=<ms>[&after=<ms>]`

- 原用户会话、有效终端、当前机主及授权epoch共同限制查询；客户端不传TB设备ID或key。
- 时间区间为报告时间`[startTs,endTs)`，最长24小时，时间必须为非负安全整数；`after`在区间内，续页按报告时间严格前进。固定页最多500条，返回`nextTs`（下一页after值，等于本页最后reportTs）；没有更多为null。不能按GNSS fix时间分页。
- 返回 `{deviceId,simulated,historyId,startTs,endTs,points,nextTs,enabled,availability,syncState}`。
- `historyId`为随机UUID或null，标识当前归属下的历史数据集，供客户端校验分页一致性和隔离地图缓存。界面使用正常的设备与日期信息。
- point为`{reportTs,breakBefore,location}`，location为原有五字段GNSS对象或null（错误/无fix）。`breakBefore`表示轨迹应在此点前断开。后端校验报告设备、授权期、版本与序号，在续页内部读取after对应的前置样本以保留跨页授权断段，再过滤该样本。首点缺少可核实的前置样本时开始新段。null中断依据继续保留。
- `enabled`表示记录是否开启，`availability`为`preparing/ready`，`syncState`为`current/pending/incomplete`。这些业务状态供App展示准备、等待同步或记录不完整的提示。平台失败返回503。服务端查询结束前再次核对机主、授权期、历史数据集及平台映射。
- 映射、机主标识、授权epoch、许可版本、连接/会话、序号、源报告与投递队列计数留在后端。RPC `get_telemetry_history_access(p_device_id,p_owner_id,p_session_id)`仅允许`service_role`执行，handler传入已验证用户和会话，数据库复核账号、有效终端、Auth会话及设备归属。旧单参RPC在新迁移中删除。

App默认今日，可选前一天/后一天（不超过今天）。每次固定查询窗口按报告时间升序逐页加载，最多2000条。界面用实际“记录时段”标明统计范围，不展示截断条数提示，也不把所读时段称为全天或最新记录。后台继续投递，页面只在前台和位置展开时刷新；重复读取不写入历史。

轨迹只累计按fix原始时间前进的有效点。无fix、许可版本改变、超过15秒的缺口及明显跳点断段。单段定位变化小于3米不增加估算里程；已知精度更差时用对应不确定性提高门槛。未知精度仍标注GPS估算，不能承诺消除全部漂移。大于15m/s的坐标跳变作为缺口不计里程，不借此判定运动安全或超速。

“有效记录时长”只累计有连续定位覆盖的区间，不等于运动时长；无点时显示无记录，不造0米行程。历史与实时最新定位分别持有，未投递完成的实时点不冒充已保存轨迹。

用户关闭原远程状态开关后停止新采集/投递，已投递历史可查询，卡片标注“已停止上报/本时段记录”。没有导航任务事件时不声称“已到达”或“运动完成”。轨迹按当前授权epoch隔离，跨授权期/任务行程归并另行设计。

## 协调发布

新历史合同与旧App解析不兼容。新版App解析`historyId`与`breakBefore`，同一设备在分页途中更换数据集时拒绝合并整次结果。此次同时收紧远程状态公共Status，机端报告的`transport`保留在内部验证，公共采样DTO去掉该字段。

发布时先完成新版App分发准备与SQL/函数包核对，再暂停远程状态与历史两个入口的流量并排空在途请求。在事务中应用`20261112010000_private_history_projection.sql`，生成随机历史标识并替换RPC权限，随后切换配套`remote-history`与`remote-state`函数，再开放入口并核验新App的历史分页、授权断段、普通机主RPC拒绝及状态读取。旧App需要更新后使用新合同。迁移前后的接口与App应作为同一发布单元审查。

该迁移只为已有平台映射补充随机历史标识，已有授权期、许可版本、投递状态与原始历史保持各自真值。当前工作仅完成本地源码和隔离验证，线上收口状态以实际部署验收为准。
